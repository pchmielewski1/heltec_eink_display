## Findings

### #1 — BUG (critical): `lastMappedTs` freeze after >6h gap

**Location**: `cadenceOnObservedTimestamp()` in `src/main.cpp`

When a sensor is silent for more than `CADENCE_MAX_INTERVAL_SEC` (6 hours),
the interval is rejected but `lastMappedTs` is never updated.
All subsequent observations compute an ever-growing interval from the stale timestamp,
permanently blocking the cadence model.

**Fix**: Update `lastMappedTs = tsEpoch` even when the interval is rejected,
so the next observation starts from a fresh baseline.

### #2 — BUG (minor): double confidence increment per wake cycle

**Location**: `cadenceOnObservedTimestamp()` and `cadenceApplyWakeOutcome()` in `src/main.cpp`

When a mapped update arrives during a wake window:
- `cadenceOnObservedTimestamp()` increments confidence by `+CADENCE_CONFIDENCE_INC_HIT`
- `cadenceApplyWakeOutcome()` increments confidence by `+CADENCE_CONFIDENCE_INC_HIT` again

Result: +16 per hit instead of +8 as designed in the spec.

**Fix**: Remove confidence increment from `cadenceOnObservedTimestamp()` — wake outcome
handler is the canonical place for confidence updates after sleep cycles.
